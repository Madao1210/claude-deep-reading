# Deep Reading · Claude Code 深度阅读技能

[English](README.en.md) | 中文

**Token 效率优先的读书流程**：章节原文只在 fork 子代理里读，主会话只收讲解和记忆。
*(A token-efficient deep-reading skill for Claude Code.)*

## 它解决什么问题

把一本长书一段段贴进对话来读，token 会随书厚线性增长——读到后面，每一轮都在重复搬运前面的原文。这个工具把"读"和"记录"拆成两个角色：

| 角色 | 干什么 | 开销特征 |
|---|---|---|
| **主会话**（主持人） | 派任务、收讲解、存记忆、记账 | 每章近乎固定，**与章节大小无关** |
| **fork 子代理**（研究员） | 闭门读完一章原文，交回笔记＋讲解 | 随章节大小增长 |

实测（12 章、14.8 万字符的公版书，2026-09-23 作者本机测量）：

- 主会话每章只增加约 **1.7 万 token**（稳态均值 16,996），与章节字符数相关系数 **r = -0.36**
- 全书 12 章原文进入主会话 **0 次**
- 全部原文工作量由子代理承担（合计 1645 万 full token，其中约 95% 为缓存重读）

## 功能

- **导入**：EPUB / Markdown / 目录 → 按章拆分（幂等，源没变就不重做）
- **逐章精读**：子代理分节读原文，输出「按行文顺序的讲解」＋「带段落定位 `[n]` 的记忆」
- **跨会话续读**：状态存盘；记忆带内容哈希，原文变了自动作废重读
- **已读复用**：已读章节不重读，直接基于记忆讲解
- **导出**：`reading.md`（脚本拼接，一字不改写）；讲解可再拼成 EPUB
- **用量记账**：每条操作记入账本（只追加），`--report` 出逐章报表

## 快速开始

要求：Claude Code、Node.js ≥ 18、git。

```bash
git clone <仓库地址> deep-reading
cd deep-reading
npm install
```

npm 直接依赖只有 3 个：`@storyteller-platform/epub`（解析 EPUB）、`turndown`（HTML→Markdown）、`yazl`（写 EPUB）。

在仓库目录里启动 Claude Code，然后直接说：

- 「读这本书：/path/to/book.epub」——导入拆章
- 「精读第 3 章」/「继续读」——逐章精读（fork 子代理干活）
- 「导出阅读笔记」——拼接导出 `reading.md`
- 「把讲解导出成 EPUB」——`export-epub.mjs` 把 `lecture/` 拼成 EPUB

所有数据都在 `books/<ID>/` 里（已在 `.gitignore` 中，不会误提交；换电脑把 `books/` 拷走即可）。

## 数据目录 `books/<ID>/`

| 路径 | 内容 | 谁写 |
|---|---|---|
| `chapters/NNN.md` + `NNN.map.json` | 原文事实（带段落索引） | 只由 split.mjs |
| `memory/NNN.md` | 章节记忆（每条主张带 `[n]` 定位） | fork 子代理 |
| `lecture/NNN.md` | 讲解正文（EPUB 导出的来源） | fork 子代理 |
| `user/NNN.md`、`user/state.md` | 用户想法、用户理解状态 | 主会话 |
| `reader.md` | 阅读目的与偏好 | 主会话 |
| `exports/` | 导出产物 | checkpoint / export-epub |
| `usage.jsonl` | 用量账本（只追加） | usage.mjs |

## 工具

| 工具 | 作用 | 示例 |
|---|---|---|
| `tools/split.mjs` | 导入拆章（幂等） | `node "tools/split.mjs" --src <epub/md/目录> --book <ID>` |
| `tools/read.mjs` | 只读原文：索引 / 分节 / 定位 / 搜索 | `node "tools/read.mjs" --book <ID> --chapter 3 --from 1 --max-bytes 12000` |
| `tools/checkpoint.mjs` | 写记忆/讲解/用户内容；状态；导出拼接 | `node "tools/checkpoint.mjs" status --book <ID>` |
| `tools/usage.mjs` | 用量记账与报表 | `node "tools/usage.mjs" --book <ID> --report` |
| `tools/export-epub.mjs` | 把 `lecture/` 讲解拼成 EPUB | `node "tools/export-epub.mjs" --book <ID>` |

## 硬规则（写进技能，部分由工具强制）

1. 四类信息分开存：原文事实（`chapters/`）｜AI 解释（`memory/`）｜用户想法（`user/NNN.md`）｜用户理解状态（`user/state.md`）
2. 记忆每条主张必须带段落定位（`[n]` 或 locate 短语），缺定位不给保存
3. 引号逐字；做不到就转述并去掉引号；跨段合并推断必须标注
4. 记忆 `complete` 后不回改（内容哈希＋方法版本守卫）
5. 导出只做脚本拼接，不让模型重写任何内容
6. 章节原文不进入主会话：读原文只发生在 fork 子任务内部

## 实测数据（2026-09-23）

12 章、148,321 字符公版书全流程（导入 → 逐章精读 ×12 → 导出）：

- 主会话·新增：稳态（源文档 4–13）12,699–20,844，**均值 16,996**；与章节字符数 **r = -0.36**
- 主会话 cacheRead 约 0.50M → 0.80M（+约 3.4 万/章）——随会话长度增长的固定成本，与书无关
- 子代理·full：0.82M–2.40M/章，驱动因素是 fork 自身请求数（16–38 次/章），其中约 95% 为缓存重读
- 全书合计：主会话新增 **305,077** vs 子代理 full **16,455,390**（按非缓存口径 305,077 vs 889,182）
- 导出 `reading.md`：269,583 字节（24 个文件脚本拼接，一字未改写）

## 目录结构

```
.
├─ .claude/skills/
│  ├─ deep-reading/           # 入口技能（在仓库目录启动 Claude Code 即可用）
│  └─ deep-reading-chapter/   # 单章精读 fork 子技能
├─ tools/                     # 5 个命令行工具（Node，无构建步骤）
├─ books/                     # 你的书与阅读数据（已 gitignore）
├─ package.json               # 3 个直接依赖
└─ README.md
```

## 装到已有项目（可选）

把 `.claude/skills/` 下两个技能目录拷进你项目的 `.claude/skills/`；把 `tools/` 和 `package.json` 放到任意位置并 `npm install`；再把两个技能文本里的 `tools/…` 命令前缀改成实际路径。注意两个技能必须放在同一技能目录下（fork 子技能要能被 `Skill` 工具调用到）。

## 已知边界

- 源格式：EPUB / Markdown；PDF 不支持
- 不做跨章分析、主题词/实体词、批注可视化、伴读模式
- 主会话的 cacheRead 仍随会话变长增长（与书无关的固定成本）
- 接口是作者自用打磨出来的，可能继续调整
